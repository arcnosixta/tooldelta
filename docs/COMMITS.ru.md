# Что сделано по коммитам и зачем

Подробные сообщения каждого коммита можно прочитать командой:

```powershell
git -c safe.directory="E:/Новая папка" log --format=full
```

Файловая система этой рабочей папки не хранит сведения о владельце, поэтому Git
может требовать `safe.directory`. В процессе создания использовалось разрешение
только для конкретной команды; глобальные настройки доверия не менялись.

## 1. Основа и выбор направления — 90392a6

Проверены несколько направлений и существующие конкуренты. Сохранены источники,
снимок звёзд GitHub, обоснование узкой задачи и план проверки спроса.
Созданы структура Python-пакета, метаданные сборки, MIT-лицензия и gitignore.
Зачем: принять объяснимое продуктовое решение и получить переносимую основу,
которую можно устанавливать и развивать без тяжёлого стека.

## 2. Ядро проверки контрактов — f2da81f

Добавлены загрузчик и сравнение input/output схем. Учтены обязательные поля,
типы, enum, вложенность, границы, дополнительные свойства, описания и hints.
Появились уровни breaking/review/info, инструкции для ревьюера и SHA-256.
Зачем: заменить шумный текстовый diff объяснениями последствий для вызовов агента.
14 тестов подтвердили основное поведение. Неизвестные конструкции явно требуют
ревью, а hints не выдаются за реальные разрешения.

## 3. CLI, отчёты и пример — 62563c9

Добавлены diff/snapshot/demo, четыре формата вывода, пороги CI и защита входных
файлов от перезаписи. Автономный HTML содержит фильтры, поиск, before/after и
экспорт JSON. Сохранены демонстрационные каталоги и реальные отчёты.
Зачем: дать пользу одним запуском и удобный артефакт для code review.
22 теста проверили CLI, коды возврата, запись и экранирование HTML.

## 4. Пограничные случаи — 6c5533a

Исправлены равенство чисел 1/1.0 в enum, отличимость от true, вложенные неизвестные
ограничения в новых свойствах и пути с символами ~/.
Зачем: не пропускать требующие ревью схемы и не создавать ложные изменения enum.
Всего 29 тестов, включая 40 направленных проверок границ внутри одного теста.

## 5. Подготовка к открытому репозиторию

Завершены английский и русский README, точные правила и ограничения, инструкции
для участников, security policy, changelog, шаблоны issues/PR и исследование рынка.
Настроен GitHub Actions для нескольких ОС и версий Python, сборки пакета и
браузерных проверок. Добавлен воспроизводимый браузерный smoke test и скриншот.
Вывод CLI приведён к UTF-8, чтобы JSON с не-ASCII символами переносимо читался.
Зачем: сделать проект понятным внешнему пользователю и проверить, что пакет
работает после установки, а HTML — в настоящем браузере.

На этом этапе репозиторий был создан локально, remote ещё не был настроен.

## 6. Публикация репозитория и ссылки проекта

По запросу пользователя создан публичный репозиторий
[arcnosixta/tooldelta](https://github.com/arcnosixta/tooldelta), настроен origin,
пять отдельных коммитов отправлены в main с сохранением истории и русских
описаний. Добавлены темы репозитория, ссылки в README и метаданные Repository,
Homepage и Issues в Python-пакете. Запущен первый GitHub Actions.
Зачем: сделать исходники доступными другим разработчикам, сохранить понятные
этапы реализации и связать устанавливаемый пакет с официальным репозиторием.

Точные hashes смотрите в git log или на GitHub. PyPI-пакет и release не публиковались.

## 7. Реальные контракты и снижение шума — 808ec75

Сняты каталоги двух версий официального MCP Filesystem Server без вызова его
файловых инструментов. Обнаружено minItems: 1 у read_multiple_files.paths.
Сохранены происхождение, зависимости и upstream-лицензии. Исправлены лишние
замечания для boolean additionalProperties и нулевых минимальных размеров.
Зачем: подтвердить пользу реальным случаем и уменьшить число необязательных ревью.
33 теста прошли; историческое окружение baseline явно описано.

## 8. Публичное браузерное демо — eb94b41

Добавлены готовый пример, реальное обновление и локальное сравнение пользовательских
JSON через тот же Python-движок в Pyodide worker. Нет передачи каталогов серверу.
Настроены GitHub Pages, метаданные страницы, sitemap, ошибки, отмена и скачивание.
Зачем: дать человеку попробовать инструмент по ссылке без установки и регистрации.

## 9. Проверка сетевого трафика браузера — f681612

Уточнён тест после обнаружения внутренних edge:// страниц при скачивании файла:
он проверяет HTTP(S)-запросы всего контекста, включая worker, и разрешает только
статические GET к демо и закреплённому Pyodide. Зачем: проверить отсутствие
отправки каталогов, не принимая локальный интерфейс Edge за внешний запрос.

## 10. Имя пакета и подготовка выпуска 0.2.0

Проверена занятость PyPI-имени: tooldelta принадлежит другому проекту.
Distribution и CLI переименованы в mcp-tooldelta, Python-пакет — в mcp_tooldelta.
Обновлены импорты, ресурсы, браузерный worker, CI и инструкции; старый пакет не
попадает в новый wheel. Зачем: исключить конфликт установки и путаницу с чужим ПО.
Подготовлены release notes, реальные доказательства, скриншоты, короткая запись
демо и тексты публикаций. Пользователю доступны исходники и готовые артефакты.
