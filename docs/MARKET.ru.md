# Выбор направления: ToolDelta

Дата исследования: 6 октября 2026 года. Это ограниченный обзор открытых
источников, а не полное исследование рынка или прогноз количества звёзд.

## Что проверено

Сопоставлены три направления: упаковка контекста для AI, наблюдаемость агентов,
совместимость и безопасность MCP. Проверены README конкурентов, спецификация MCP
и текущие данные публичного GitHub API. Числа ниже — снимок на дату исследования;
они меняются и не измеряют выручку или число активных пользователей.

| Направление / проект | Звёзды | Вывод для небольшого нового проекта |
| --- | ---: | --- |
| [Repomix](https://github.com/yamadashy/repomix) | 28 716 | Сильный сигнал интереса к простой утилите для AI-разработчиков; универсальный упаковщик контекста уже занят зрелым продуктом. |
| [OpenLIT](https://github.com/openlit/openlit) | 2 817 | Наблюдаемость востребована, но полноценная платформа требует большого числа интеграций и эксплуатации. |

Источники чисел: `https://api.github.com/repos/{owner}/{repo}`, поля
`stargazers_count` и `forks_count`. Страницы репозиториев — источники возможностей,
а не независимая оценка качества. Дополнительно изучены
[Toolpin](https://github.com/proofofwork-agency/toolpin) и
[AgentGate](https://github.com/wookat/agentgate): lockfile и контроль MCP-конфигураций
тоже не являются свободной нишей.

## Почему выбран diff контрактов MCP

[Спецификация MCP tools](https://modelcontextprotocol.io/specification/2025-06-18/server/tools)
задаёт `inputSchema`, необязательную `outputSchema`, описания и annotations.
Изменение этих полей — конкретная причина, по которой ранее работавший вызов
агента может перестать работать. Спецификация отдельно требует считать
annotations недоверенными без доверия к серверу.

Гипотеза: авторам MCP-серверов и командным пользователям полезен небольшой
инструмент, который сравнивает уже сохранённые каталоги, не запускает код
сервера и даёт ревьюеру объяснение каждого изменения. Это вывод из источников,
а не подтверждённое интервью с покупателями. Наиболее подходящее направление
здесь означает сочетание узкой задачи, реалистичной реализации и простой
демонстрации; не доказанный максимум будущих звёзд.

Отличие ToolDelta в первой версии: нулевые runtime-зависимости, полностью offline
режим, объяснения направления совместимости input/output, самостоятельный
HTML-отчёт, JSON и Markdown для CI. Не заявляем уникальность всей идеи: Sentinel
уже решает близкую задачу, Snyk покрывает безопасность, Toolpin — поставку.

## Границы первой версии

- Принимать массив tools, объект `tools`, `result.tools` из JSON-RPC.
- Сравнивать обязательность, типы, enum, числовые/строковые/массивные ограничения,
  вложенные свойства, outputSchema, annotations и описания.
- Разделять доказанные локальные ограничения, изменения для ручного ревью и
  информационные изменения. Не обещать полную проверку JSON Schema или безопасность.
- Неподдержанные конструкции (`$ref`, композиции и другие) отправлять на ревью,
  не выдавая отсутствие поддержанных изменений за доказательство совместимости.
- Не соединяться с MCP-сервером, не запускать команды, не собирать телеметрию.

## Как проверять интерес после публикации

1. Показать 30-секундный пример: read-only инструмент стал write-capable и получил
   обязательный параметр. Приложить реальный отчёт, а не только обещание.
2. Опубликовать MIT-репозиторий с английским README, русской документацией,
   тестами, CI и понятными задачами для новых участников.
3. По договорённости с пользователем подготовить Show HN / пост в MCP-сообществе.
   Не размещать сообщения автоматически и не покупать звёзды.
4. Первые 2–4 недели считать запуски примера по добровольным отзывам, полезные
   issues, интеграции и повторное использование. Звёзды — вторичный сигнал.
5. Если пользователи не присылают реальные контракты для проверки, пересмотреть
   гипотезу. Следующие функции определять по кейсам, а не по размеру списка фич.

Название ToolDelta — рабочее; доступность имени на PyPI, домена и товарных знаков
не проверялась. Пакет устанавливается из исходников, публикация не выполнена.
